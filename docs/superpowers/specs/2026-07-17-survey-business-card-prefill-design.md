# 설문 결과 기반 명함 제작 설계

## 목적

관리자가 명함 제작 탭에서 설문 참여자의 이름을 검색하고, 정확한 응답을 선택해 명함 정보를 자동으로 채울 수 있게 한다. 명함의 희망 직업은 기존 예시 5개가 아니라 직업 탐험 데이터의 전체 107개 직업에서 선택할 수 있게 한다.

## 범위와 권한

- 결과 조회와 불러오기는 기존 owner 관리자에게만 제공한다.
- 일반 설문 참여자와 비로그인 사용자는 다른 참여자의 이름이나 개인정보를 검색할 수 없다.
- 이름이 없는 응답은 검색 결과에 표시하지 않는다.
- 기존 Firestore 읽기 정책과 `testResults` 문서 구조는 바꾸지 않는다.

## 사용자 흐름

1. owner 관리자가 `명함 제작` 탭을 연다.
2. 상단의 `설문 결과 불러오기`에서 이름 일부 또는 전체를 입력한다.
3. 일치하는 응답을 최대 최신순으로 보여 준다. 각 행에는 이름, 이메일, 소속(센터), 응답일, 최종 꿈을 표시한다.
4. 동명이인은 위 식별 정보를 보고 한 응답을 선택한다.
5. 선택된 응답으로 명함 입력값을 채운다.
   - 이름: `participantName`
   - 이메일: `participantEmail`
   - 학교/소속: `centerName`
   - 희망 직업: `dreamChoice` 또는 기존 설문의 대표 직업
   - 한 줄 목표: `resultSummary`
6. 관리자는 필요하면 모든 입력값과 직업을 다시 바꾼 뒤 인쇄한다.

## 직업 선택

- `careerCatalog`을 단일 원본으로 사용해 107개 직업을 검색·선택한다.
- 각 항목은 직업명과 직업 상세 데이터의 이모지를 표시한다.
- 설문 응답이 `아직 더 찾아보는 중`이면 희망 직업은 비워 두고, 관리자가 목록에서 고르게 한다.
- 기존 다섯 직업 전용 테마 목록과 관련 상태는 제거한다. 명함은 공통 디자인을 유지하고 선택 직업의 이모지를 사용한다.

## 구성 요소와 데이터 경계

- `businessCardPrefill` 변환 함수: `StoredTestResultRecord`를 명함 입력값으로 안전하게 변환한다. 이름·이메일·센터명·최종 꿈·요약을 정규화한다.
- `SurveyResultLookup`: owner 모드에서만 `fetchAdminResults`를 호출하고, 이름 검색·동명이인 선택·불러오기를 담당한다.
- `CareerPicker`: `careerCatalog` 기반의 검색 가능한 107개 직업 선택 UI를 제공한다.
- 명함 편집·미리보기·인쇄는 기존 컴포넌트의 역할을 유지한다.

## 예외 처리

- Firebase 연결이 없거나 읽기에 실패하면 검색 불가 안내를 표시하고, 수동 명함 입력은 계속 가능하게 한다.
- 일치하는 이름이 없으면 빈 결과 안내를 표시한다.
- 이름 없는 응답은 개인정보 식별이 어려우므로 검색 결과에서 제외한다.
- 최종 꿈이 직업 목록에 없거나 `undecided`이면 직업 선택을 비워 두되, 결과 요약은 불러온다.

## 검증

- 응답 레코드가 명함 사전 입력값으로 정확히 변환되는지 테스트한다.
- 같은 이름의 여러 응답을 이메일·소속·응답일·최종 꿈으로 구분하는 검색 결과를 테스트한다.
- 전체 107개 직업이 검색 가능한 선택 목록에 포함되는지 테스트한다.
- 이름 없는 응답과 `undecided` 꿈의 처리, Firebase 미연결 상태를 테스트한다.
- 전체 테스트, 데이터·분포·명함 검사, TypeScript/Vite 빌드를 실행한다.
